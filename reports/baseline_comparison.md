# A/B/C 对照实验（当前仅 B、C 两档）

A 档（无授权、无规则）不复现：生产代码中不存在跳过用户归属过滤的入口，为对照实验人为制造一条旁路，会让仓库长期保留一条可被误用的路径。因此本报告只能量化「确认、幂等与恢复」的收益，不能量化授权与业务规则本身的收益。

## 逐条结果

## 结论

- 业务结果达成率无法区分两档：B 在没有确认的情况下同样能完成取消。差别不在结果，而在用户是否被询问过。
- 未确认写入率是本次实验唯一能区分两档的指标：B 的每一笔成功取消都对应一条没有确认记录的写操作，C 全部有。
- 本次未覆盖重复写入。B 档仍受 `refund_requests` 上 `kind='cancellation'` 唯一索引的约束，但服务端幂等层面的收益需要独立的重复提交用例才能量化。
- B 无法写审计日志：`operation_logs` 对 `confirmations` 有复合外键，没有确认记录就写不进去。这不是实现遗漏，而是确认机制缺失的直接后果。

生产 API 固定使用 C 档；B 档只存在于 `baselines/` 与评测入口。
